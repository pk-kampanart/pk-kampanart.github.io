Chapter 2: File System

  • File is the sequence of byte(typically 8 bits).

  • For the system, file have no meaning or structure, just a sequence of byte.

  • The meaning of file depend on program that use that file type.

  • od(“octal dump”) print bytes and visual representation of that file

    $ od -cb *file*

  • In Unix every thing is a file(sequence of byte), keyboard input is also a file(sequence of bytes), data flow in pipes is also a file(sequence of byte).

  • newline(\n), backspace(\b), tab(\t) and carriage return(\r) is special characters. each of them has 1 byte long like other characters.

    • if \b is in the file the system assume that you want to delete previous character like you press BackSpace on keyboard.

    • how \t is interpreted depend on your program like terminal to display it.

    • When you press Return key, you send the \r and \n, but store only \n.

    • Unix use \n (“LF”(“line feed”)) to terminate line, but some system like Windows use \r\n (“CRLF”).

      Note: “line feed” is synonym for “new line”

  • Programs use system call (a subroutine in the kernel) called read to retrieve the data on file.

    • read return the next part a file and how many byte of the file were returned, so “zero byte returned mean EOF”

      Note: Notice how EOF don’t have any special character representation, it make sense because all system can agree that zero byte mean it end(“EOF”).

      Note: In the book it’s explained that cat buffered in put to show all of it in single output, you can use cat -u to unbuffered it (print immediately after you press enter), but flag -u in present day cat is ignored (See man cat) cause cat work like cat -u by default.

  • file command use to “guess” the usage of the file(file type).

  • Runnable file is the file that start with magic numbers that difference depend on system.

  • Usually program that use text as the input like sort or grep don’t behave properly when the input is 30,000 byte of text file without new line. This is because most program have maximum length of line.

  • Every process have current directory (use pwd), if the process create child process it inherit current directory, but child process can change current directory without affect parent process. The purpose is to organize related file in the same directory.

  • du show disk usage in that directory

  • Directories is similar to regular file that can’t write on like regular file, they contain their permission and directory name

  • The modification date is also contain in the file.

  • chmod

  • Permission like -rwxr-xr-x, not contain in the file itself but in the system structure called index node(inode).

  • Both permission and modification time store in inode.

  • inode contain 3 times

    • time that the file was modified.
    • time that the file was last used (read or executed).
    • time that the inode it self modified (like change permission).

  • ls -t sort file by modified time, use ls -ut to sort it again by last changed inode information or last read.

  • ls -i list i-number (inode number) of files in decimal, it’s the real name of file in system

  • The filenames in directory is call link, because it contain link of filename to i-number. When delete file with rm it’s not delete the inodes itself but delete the link to the inodes.

  • The same i-number can appear in more than one directory.

  • When you use ln to create link to a file (hard link), the i-number of that new file is the same as linked file, so ln actually give two name to the same file.

  • With cp you can create 2 file with difference inode.

  • You can’t link file across file system (df to report free space of mounted subsystem)

Chapter 3: Shell

  • date; whoami
  • (date; whoami) | wc -l
  • (date; whoami) | tee save | wc -l
  • (sleep 5; date) & date: run date and delay date in the background show up 5 second later.
  • echo hello > junkfile is the same as >junkfile echo hello.
  • ( ... ) run commands in sub-shell.
  • { ... } run commands in current shell.
  • glob basic characters *, ?, [ccc].
  • >file, >>file direct or append standard output to file
  • <file take standard input from file
  • n>file, n>>file direct or append output to file descriptor n
  • n>&m merge output form fd n to fd m
  • n<&m merge input from fd n to fd m

Chapter 5: Shell Programming

  • case, for, which, if-else, test, while-until

  • trap: to catch interrupt

  • $- list of options apply to the shell.

    $ echo $-
himBHs
$ set -e
$ echo $-
ehimBHs

  • $$ process-id of current shell

  • $! process-id of last background process (start with *command* &)

  • $@ and $* blank in argument are rescanned.

  • "$*" is single word composed of all arguments.

  • "$@" blanks in argument are ignored like original arguments. Conclusion: only "$*" are behave differently.
